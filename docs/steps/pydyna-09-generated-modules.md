# PyDyna T1.1: drop generated protobuf modules from the code collections (27 Nov 2026)

Finding of the CR-4 follow-up Linux check (docs/steps/pydyna-08-cr4-store.md): `search_pydpf_core` returned `src/ansys/grpc/dpf/available_result_pb2.py`, a module generated by `protoc` (serialized descriptor bytes, no API a script uses). On Linux: 336 of 13014 `pydpf_core` records, from 52 files (user, 27 Nov 2026).

## Change

| File | Change |
| --- | --- |
| `champion/specialists/pydyna/records.py` | `GENERATED_ENDINGS = ("_pb2.py", "_pb2_grpc.py")`; `keep_code_path` returns False for a file name ending in one of them (case-insensitive) |
| `champion/specialists/pydyna/source_data.py` | doc: the generator drops them too (it uses the same rule) |
| `tests/pydyna/test_pydyna_records.py` | six cases: `*_pb2.py`, `*_pb2_grpc.py`, upper case dropped; `__init__.py` in the same folder, `pb2_helpers.py` kept; `*_pb2.pyc` dropped by its suffix |

`keep_code_path` is shared: it applies to `pydyna_api`, `pydpf_post` and `pydpf_core`, both when building and when filtering hits, and in `source_data.py` when the JSONL is generated.
